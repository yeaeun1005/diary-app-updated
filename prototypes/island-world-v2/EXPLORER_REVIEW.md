# 탐험가·승선·잠수 — 2026-09-17 실행 결과

승인: 사용자의 “괜찮아. 계속 가자”. 직전 해안·바다 작업을 보존하고, 후속으로 남겼던 기본 캐릭터와 승선/잠수 동작을 로컬 시제품에서 구현했다. 외형의 세부 모습은 이번 검토용 결과이며 사용자 최종 채택과 구분한다.

## 직접 해보기

주소: http://127.0.0.1:8766/ — 이 컴퓨터에서만 접속하는 메모리 연습 공간이다. 설치·로그인·운영 접속은 필요 없다. 새로고침하면 가상 기록이 초기화된다.

1. ‘부두로 걷기’를 누르고, 부두 가까이에서 아래 ‘바다로 · 배 타기’를 누른다. 부두 끝으로 걸어가 배에 오른 뒤 출항하고 기존 우리 반 바다가 열린다.
2. 지도의 ‘길을 따라 둘러보기’ → ‘내 안으로’를 선택한다. 입구에 도착한 뒤 아래 ‘내 안으로 · 열기’를 누르면 뛰어들기/물결 연출 후 기존 개인 활동을 연다.
3. 연출 중 ‘바로 들어가기’로 건너뛰거나 ‘취소’/Escape로 취소한다. 상단 ‘내 안으로’는 연출 없이 바로 활동을 여는 빠른 길이다.

## 완료

- 원본 탐험가 캐릭터: 둥근 얼굴과 눈, 모자/목수건/배낭/말아 둔 지도/신발. 걷는 팔·다리, 방향 전환, 쉬는 동작과 눈 깜박임.
- 내 섬에서 승선·출항과 물결, 잠수·물 튀김·수면 아래 색 전환. 기존 활동·바다 연결 함수를 끝에서 한 번만 호출한다.
- 연출 중 일반 이동을 멈추고, 취소·건너뛰기·기존 동작 줄이기 설정에 대응한다. 화면을 닫고 돌아오면 진입 직전 위치와 시점을 유지한다.
- 기존 바다와 친구 섬의 캐릭터도 같은 모델을 사용한다. 기존 크기와 머리 위 표식이 맞도록 모델 내부만 축소한다.
- 작은 화면에서 연출 안내가 조이스틱/이동 안내와 겹치지 않도록, 연출 중 이동 안내를 숨긴다.
- 외부 모델·이미지·유료 API·패키지 설치 없이 기존 Three.js로 구현했다.

## 실제 화면에서 확인

Mac의 Codex 내장 Chromium에서 UI를 직접 조작했다. 외부 자동 브라우저 스크립트나 운영 데이터는 사용하지 않았다.

| 조작 | 확인 결과 |
|---|---|
| 시작 지점 → 부두로 걷기 → 승선 → 출항 | 단계별 자세와 이동이 보이고 기존 우리 반 바다가 열림 |
| 바다 → 내 섬 | 원래 부두 위치로 복귀, 이동 입력은 해제됨 |
| 내 섬 → 잠수 입구까지 걷기 → 잠수 | 뛰어들기와 물결 뒤 기존 감정 일기쓰기 화면이 열림 |
| 개인 활동 닫기 → 다시 잠수 → 취소 | 입구 위치 복원, 다시 행동 버튼 사용 가능 |
| 잠수 다시 완료 → 복귀 | 반복 진입으로 화면이 잠기지 않음 |
| 390×844 화면에서 잠수 건너뛰기 | 기존 활동 화면 즉시 열림 |
| 작은 화면 승선 안내 | 이동 안내와 겹치지 않음. 실제 손가락 멀티터치 검증과는 구분 |
| 우리 반 바다 → 가상 친구 산호 선택 → 항해 → 친구 섬 → 귀항 | 기존 방문 흐름 유지, 친구 섬에 새 캐릭터와 머리 표식 표시, 새 내 섬으로 복귀 |
| 콘솔 오류/경고 | 위 확인 구간에서 없음 |

친구 섬의 새 지형과 공감 동작 전체를 이번에 검증한 것은 아니다. 실제 학생이나 운영 Firebase에는 접속하지 않았다.

캡처는 `renders/harness/` 아래 무시된 테스트 산출물이다.

- `v2-explorer-character.png`: 실제 조작으로 확대하고 시점을 낮춘 탐험가
- `v2-explorer-start.png`: 기본 시작 화면
- `v2-explorer-boarding.png`, `v2-explorer-sailing.png`: 승선·출항 시작
- `v2-explorer-dive-frame-2.png`, `v2-explorer-dive-frame-4.png`: 잠수와 물결 중간 장면
- `v2-explorer-mobile-motion.png`: 최종 390×844 승선 화면
- `v2-explorer-friend.png`: 기존 친구 섬의 새 캐릭터

## 코드로 검사한 항목

`node prototypes/island-world-v2/check-passages.cjs` 통과. 기존 Three.js와 실제 캐릭터/전환 함수를 메모리에서 실행하며, 브라우저·네트워크·DB는 사용하지 않는다.

- 승선/출항, 잠수/물결 단계와 목적지 한 번만 열기
- 진행 중 중복 실행 차단, 취소와 건너뛰기 중복 호출
- 캐릭터/배의 위치 복원, 귀환용 위치 보존
- 동작 줄이기 설정의 즉시 연결
- 캐릭터 좌표가 유효한 숫자인지, 기존 방문 크기와 표식 높이

`node prototypes/island-world-v2/check.cjs`도 통과. 메모리 게시판의 읽기/쓰기, 공개 답 0/2/3개 경계, 교사 검토, 익명 사본, 수정 시 공개 철회, 이름 보호, 게시판 저장 시 섬 자료 불변, 어휘 중복 방지, 별도 게시판 렌더러 없음, Firebase 격리와 생성 HTML 문법을 검사했다.

이 검사는 운영 기능 전체나 실기기 테스트를 대체하지 않는다.

## 성능

동일 Mac/내장 Chromium, 1440×900, 픽셀 비율 상한 1.5, 기본 그림자, 마음 말 8개/식생 24개. `?compare=1`로 위치 (-4,8), 회전 -0.45, 높이 각도 0.68, 거리 22를 고정했다.

| 항목 | 직전 해안 버전 | 이번 탐험가 버전 |
|---|---:|---:|
| FPS | 119.4 | 119.3 |
| 프레임 시간 | 8.37ms | 8.38ms |
| 그리기 호출 | 239 | 257 |
| 삼각형 수 | 441,594 | 452,031 |

캐릭터 디테일로 같은 위치에서 삼각형 수가 약 2.4% 늘었다. 이 환경에서 FPS는 비슷했으며 성능 향상을 주장하지 않는다. 최초 장면 생성+첫 렌더는 이번 약147ms였으며 전체 다운로드/시작 시간과 다르다. 캐릭터 자체는 35개 메시/16,801개 삼각형(가려질 때 보이는 간략 실루엣 포함)이다. 작은 부품은 같은 재질끼리 묶었다. 측정 원본은 `v2-explorer-metrics.json`.

실제 휴대폰·크롬북, 오래 실행했을 때 발열과 배터리, 저사양에서 연출 중 프레임은 미확인이다.
