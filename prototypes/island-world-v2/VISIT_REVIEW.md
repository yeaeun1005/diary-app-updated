# 친구 섬과 로그인 첫 화면 · 로컬 확인

2026-09-17 / codex/island-world-v2 / 기반 커밋 347e610

## 달라진 화면

- 기본 주소는 바다와 섬 전경이 있는 첫 화면이다. ‘탐험 시작하기’ 또는 학생 로그인으로 내 섬에 들어간다. 선생님 로그인은 기존 교사 화면으로 연결한다.
- 첫 화면은 실제 새 섬 장면을 사용한다. 시작 화면은 초당 약 30회로 그리는 횟수를 제한하고 그림자를 반복 계산하지 않는다. 학생·선생님 입력창에 항상 보이는 항목 이름, 키보드 초점 이동을 적용했다.
- 친구 섬에 입장하면 내 섬과 같은 해안·모래사장·연못·다리·산책길이 나타난다. 공개한 기록만 식물로 나타나며 친구마다 배치가 다르다. 숨긴 기록과 일기는 장면에 전달하지 않는다. 공감은 식물 가까이에서 보낸다.
- 친구의 개인 활동 입구는 덮개로 막혀 있고, 가까이 가면 친구만 들어갈 수 있다는 안내를 연다. 부두에서 다시 배를 타고 기존 바다를 지나 내 섬으로 돌아온다.
- 도움말(?)에서 표준/가벼운 화질을 고른다. 가벼운 화질은 그림자, 픽셀 비율, 가장자리 보정을 낮춘다. 기록·지형·걷기 범위는 같고 위치·시점도 유지한다.

## 실제 컴퓨터에서 확인

Mac의 Codex 내장 Chromium, 기본 1440×900. 실제 휴대폰·크롬북 대신 컴퓨터만 확인한다는 사용자 답변을 따랐다.

- 첫 화면의 탐험 시작하기 → 새 내 섬 → 처음으로 복귀. 학생 로그인 → 새 내 섬. 선생님 로그인 → 기존 교사 화면 → 로그아웃. 연습 계정으로만 수행했다. 빈 학생 입력을 제출하면 기존 필수 입력 안내가 나온다. 로그인 창의 Shift+Tab 초점 순환도 확인했다.
- 내 섬 → 부두까지 걷기 → 승선 연출 → 우리 반 바다 → 산호 선택·항해 → 새 친구 섬 → 슬픔 식물까지 걷기 → ‘나도 그래’ 공감 → 반딧불 전달 → 오늘 이미 보냈다는 비활성 버튼 → 시점 회전 → 친구 개인 입구 차단 → 부두 승선 → 내 섬 복귀를 실제 조작했다.
- 기록 없는 여울 섬에 실제 입장해 마음 말 0개/기록 식물 0개와 기록 식물 안내가 없는 것을 확인했다. 공개된 세 마음/기록 식물 9개로 구성된 산호 섬도 확인했다. 친구 숨김 기록은 새 장면에 포함하지 않는다. 친구 화면에 어휘 합계나 공감 개수·순위를 표시하지 않는다.
- 산책 안내가 식물과 조금 떨어져 멈추는 경우를 수정했다. 마지막 접근 구간도 같은 지형·충돌 검사로 확인한 후 걷는다. 수정 후 내 섬의 우울 식물에 도착해 숨김/다시 공개 버튼을 조작했다. 위치 (3.282,14.740), 마음 말 8개/식물 24개는 전후 동일했다.
- 390×844로 컴퓨터 브라우저 창을 줄여 첫 화면, 로그인, 학생 섬의 버튼·조이스틱 배치를 확인했다. 이는 실제 터치 기기 시험이 아니다.

## 성능 확인의 범위

같은 위치 (x=-4,z=8), 같은 시점 (yaw=-0.45,pitch=0.68,distance=22), 마음 말 8개/기록 식물 24개에서 브라우저가 보고한 연속 프레임 간격이다. GPU만의 실행 시간이나 실제 저사양 기기 성능 측정이 아니다.

| 설정 | 관측 프레임률 | 평균 프레임 간격 | 화면 그리기 호출 / 삼각형 |
|---|---:|---:|---:|
| 표준 | 118.93 FPS | 8.41 ms | 257 / 452,031 |
| 가벼운 화질 | 120.00 FPS | 8.33 ms | 257 / 452,031 |

이 컴퓨터에서는 둘 다 화면 갱신 한도에 가까워 큰 차이를 입증하지 못했다. 가벼운 설정은 픽셀 처리·그림자 부담을 줄이며 지형은 줄이지 않아 표의 도형 수는 같다. 단일 장면의 관측치이며 오래 사용할 때의 발열이나 배터리, 교실 기기에서의 체감 향상은 미확인이다. 최초 장면 생성·첫 렌더는 관측 124ms/648ms였으나 쉐이더 최초 준비 등이 달라 단순 비교하지 않는다. 전체 페이지 로딩 시간도 아니다.

원본 측정: `renders/harness/v2-visit-performance.json`.

## 코드와 메모리 DB 검사

다음은 실제 UI 조작과 구분하는 자동 검사다. 최종 빌드 뒤 세 검사 모두 통과했다. 브라우저에서 마지막 확인 시 오류·경고는 없었다.

- `node prototypes/island-world-v2/check.cjs`: 게시판 읽기/쓰기, 공개 답 0·2·3개 조건, 교사 검토, 익명 사본, 수정 시 공개 철회, 이름 보호, 게시판 처리로 섬 기록 불변, 어휘 중복 방지, 추가 3D 생성 없음, Firebase 격리, HTML 구문.
- `node prototypes/island-world-v2/check-passages.cjs`: 승선/잠수 완료 한 번, 중복 실행 차단, 취소·건너뛰기·동작 줄이기, 안전한 복귀 위치, 캐릭터 형상.
- `node prototypes/island-world-v2/check-social.cjs`: 숨김 제외, 같은 감정 구역 경험 조건, 동시/같은 날 중복 공감 차단, 다른 마음에 공감 허용, 보내기 직전 공개 설정 재확인, 내 숨김 식물 보존, 친구 일기 조회 없음, 원본 학생/교사 인증 처리 함수 동일.

## 안전과 보존

운영 index.html SHA256은 작업 전후 `5f127222be13331363f4d97292c7676f05a3219db0e5f7d1a631893f37a11eaf`로 동일하다. HANDOVER.md도 시작 때와 같다. 기존 DESIGN.md 내용은 삭제하지 않고 최신 승인 절을 앞에 추가했다.

Firebase SDK·설정·시연 생성기를 제거한 메모리 DB 생성 페이지만 실행한다. connect-src 'none', 외부 글꼴 요청 제거, 서버 127.0.0.1 전용. 학생/교사 계정은 이번 창의 가상 자료이며 비밀번호는 화면에서 마스킹한다. 실제 자료 조회, 시연 학급 재생성, 패키지 설치, stash 복원, 커밋·푸시·배포는 하지 않았다.

## 미완료·미확인

- 미완료: 우리 반 바다에 멀리 보이는 섬 모형까지 새 지형으로 통일하기. 현재 바다의 선택·항해와 원경 모형은 기존 것을 재사용하고, 실제 입장한 친구 섬은 새 지형이다.
- 미완료: 나머지 세 감정 구역의 상세 아트, 임의 추가 어휘의 새 식생 배치 확장, 운영 로그인·운영 앱으로의 적용과 배포. 기존 원본은 그대로다.
- 미확인: 실제 휴대폰의 터치·동시 핀치, 크롬북, 저사양 기기의 장시간 성능, 모든 지형 경계, 모든 개인 활동·교사 업무의 전체 회귀. 교사 화면은 로그인과 진입만 확인했고 학생 추가·초기화 등은 실행하지 않았다.
