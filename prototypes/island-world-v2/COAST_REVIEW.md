# 해안·바다·조작 개선 검수 — 2026-09-17

## 승인 범위와 실제 변경

사용자가 디자인 제안에 “그러면 지금대로 해줄래?”라고 승인한 범위: 섬·해안·바다의 인상, 뒤늦게 따라오는 장소 이름표, 휴대폰 이동 조작. 현재 브랜치 codex/island-world-v2, 기반 커밋 347e610. 배포하지 않은 로컬 시제품이다.

- 시작 위치를 부두 가까운 해안으로, 기본 시점은 바다와 모래사장을 함께 보도록 변경했다. 작은 만을 포함한 비대칭 해안선을 지형과 걷기 판정에 함께 반영했다. 지도도 같은 해안 함수를 기준으로 그린다.
- 청록 얕은 물/푸른 깊은 물/해안 흰 물결/작은 햇빛 반짝임을 추가했다. 풀과 잎의 색을 또렷하게 하고 따뜻한 모래사장을 넓게 드러냈다. 야자나무, 해안 바위, 조개·풀, 부두 산호색 깃발은 중립 배경이며 학습 식생에 포함하지 않는다.
- 화면 위에서 0.18초 간격으로 뒤늦게 움직이던 장소 이름표를 제거했다. 부두에는 양면 실제 간판을 만들고, 가까이 갔을 때의 고정 행동 버튼을 유지했다.
- 왼쪽 조이스틱, 오른쪽 드래그 시점, 접이식 지도. 놓기·입력 취소·창 이탈·게시판 열기 때 이동을 멈춘다. 좁은 창에서도 조이스틱을 보여 검토할 수 있게 했다.
- 기존 우리 반 바다는 물 재질만 새 표현으로 바꿨다. 가상 친구 선택/항해/섬 입장/공감/귀환의 기존 코드는 그대로 사용한다. 그 바다에 보이는 섬 미리보기와 친구 상세 섬은 아직 이전 외형이다.
- 야자 잎은 두 묶음, 줄기는 반복 묶음으로 그린다. 꽃잎과 둥근 나무의 과도한 면 수를 줄였다. 후처리나 외부 모델/패키지는 추가하지 않았다.

## 실제 브라우저에서 확인

Codex 내장 Chromium / 이 Mac / 메모리 DB만 사용.

- 부두 안내를 눌러 실제 걷기: (-8,20)에서 (-7.124,26.438) 도착, 자동 보행 종료.
- 승선 버튼 → 우리 반 바다의 새 물 표현 렌더, 오류 없음 → 기존 귀환 이동 → 새 내 섬 복귀.
- 부두→중앙 쪽→게시판: (-7.576,0.863) 도착. 게시판 열기에서 paused=true, 입력0, 위치/시점/어휘8/기록 식생24 유지. 답 작성 전 친구 답이 가려진 상태 확인. 닫은 뒤 평온 정원(16.643,-4.079)까지 실제 보행 및 종료 확인.
- 네 감정 구역과 모든 목적지의 경로 탐색 결과는 이동 가능. 이는 모든 경계를 손으로 밟아봤다는 뜻이 아니다.
- 390×844 화면: 조이스틱 드래그로 (-8,20) → (-7.908,20.091) 이동, 놓은 뒤 입력(0,0)/active=false. 이후 오른쪽 화면 드래그에서 위치는 그대로이고 시점 좌우 -2.35→-2.11, 상하 .65→.45로 변경. 지도 열기/닫기, 기본 시점 복귀 확인.
- 기록 없는 자료에서 어휘0/기록 식생0 확인. 배경 해안 장식은 남는다.

## 전후 성능 실측

같은 1440×900, DPR 최대1.5, 기본 그림자 설정, 가상 어휘8/식생24, 캐릭터(-4,8), 시점(-.45,.68), 거리22. 새 버전은 `?compare=1`로 기존과 같은 위치·시점을 사용했다. 화면 구성/지형/재질은 이번 변경 대상이므로 완전히 동일한 장면은 아니다. 한 Mac의 비교 표본이며 크롬북 결과가 아니다.

| 측정 | 수정 전 | 수정 후 |
|---|---:|---:|
| 평균 FPS | 119.8 | 119.4 |
| 평균 프레임 간격 | 8.35ms | 8.37ms |
| 한 화면 그리기 호출 | 229 | 239 |
| 삼각형 수 | 659,710 | 441,594 |
| 장면 생성+첫 렌더 | 140.1ms | 152.0ms |

삼각형은 약 33% 줄었고 그리기 호출은 10회 늘었다. FPS는 거의 같아서 “더 빨라졌다”고 결론내리지 않는다. 초기 생성 수치는 전체 페이지/파일 다운로드 시간이 아니다. 프레임 간격은 브라우저 루프 측정이며 GPU 단독 시간이 아니다. 창 대기 등 250ms 이상 간격과 패널 정지 구간은 평균에서 제외된다.
