# 배포 후보·계정 연결 검증 — 2026-09-17

후속 승인: 사용자가 “커밋 푸시 고고”라고 답해 이 후보의 실제 게시가 허용됐다. 아래는 **게시 직전 로컬 검증 기록**이다. 이후 게시 승인 범위와 복구 방법은 release/DEPLOYMENT.md, 실제 작업 결과는 해당 커밋의 GitHub Pages 작업을 확인한다.

현재 상태는 **배포 준비 완료, 실제 게시 전**이다. 새 디자인을 기존 로그인·학습 화면에 연결한 후보와 이전 화면 복구본을 만들었다. 운영 Firebase 및 학생 자료에는 접속하지 않았다. 루트 index.html, 기존 HANDOVER.md 변경, 작업 브랜치와 미커밋 변경을 보존했다. 커밋·푸시·배포는 하지 않았다.

## 화면에서 확인한 내용

안전한 주소: http://127.0.0.1:8767/ . 이 컴퓨터의 메모리 검증본이며 새로고침하면 가상 기록이 초기화된다. 첫 화면 → 로그인 → 학생 A/B/기록 없는 학생을 선택하거나, ‘탐험 시작하기’로 가상 학생 A에 들어간다. 실제 계정을 입력하지 않는다.

- 첫 화면, 학생 로그인, 선생님 로그인과 원래 관리 화면 진입을 확인했다.
- 학생 A로 원래 감정 일기를 저장해 2개에서 3개가 됐고, 학생 B의 기록 2개는 바뀌지 않았다. 로그아웃 후 B로 들어가 B의 기록만 보이는 것을 확인했다.
- 원래 개인 활동 화면의 다섯 탭·리포트·비밀번호 변경 입구를 보존했다. 각 기능 전체를 다시 실행한 것은 아니다. 비밀번호는 변경하지 않았다.
- 직접 입력한 마음 말 ‘몽글몽글’로 감정을 수정했다. 기록은 3개를 유지하고 섬의 누적 마음 말은 5개, 기록 식물은 15개가 됐다. 다시 로그인해 누적 풍경이 유지됐다. 메모리 창 안에서의 재로그인이며 새로고침 후 영속 저장 검증은 아니다.
- 게시판에 가상 답을 쓰면 ‘선생님의 공개를 기다려요’가 표시됐다. 기존 익명 공개 답 3개가 표시됐고 개인 일기·식물 수는 바뀌지 않았다. 선생님 화면에서도 새 답이 비공개 검토 대상으로 보였다. 실제 학급 게시판에는 접근하지 않았다.
- 내 섬 부두 → 우리 반 바다 → 여울 선택·항해 → 새 친구 섬 → 식물까지 걷기 → 공감 → 부두에서 귀환 → 내 섬 복귀를 조작했다. 공감 후 같은 마음의 버튼이 ‘오늘 이미 보냈어요’로 막혔다.
- 친구 B의 마음 말 3개 중 숨긴 1개를 제외한 2개/식물 6개만 방문 화면에 나왔다. 기록 없는 학생은 마음 말 0개/기록 식물 0개였다.
- 컴퓨터에서 390×844 크기로 줄였을 때 조이스틱·시점 버튼·소리 버튼이 화면 안에 배치됐다. 실제 터치 기기 검사와는 다르다.

감정 수정 조작 중 기존 DiaryView의 성공 안내가 정의되지 않은 setMsg를 호출하는 오류를 발견했다. **배포 후보에서만 완료 안내 상태·표시를 보완**했다. 감정 분석과 저장 함수는 바꾸지 않았다. 수정 후 같은 조작을 반복해 완료 안내와 기록 반영을 확인했다. 마지막 검사에는 이전 오류 로그만 남았고 수정 후 새 오류는 없었다.

## 코드로 확인한 내용

- 기존 학생·선생님 인증 함수, 학습 저장 함수, DB 키 구조를 원본과 비교했다. DiaryView는 위 완료 안내만 예외로 허용하고 나머지를 비교했다.
- 메모리 단위 검사: A/B 저장 분리, 편집·삭제 뒤 누적 풍경 유지, 숨김 유지, 다른 학급 방문 거부, 친구 일기 미조회, 저장 실패 시 원래 동작을 확인했다.
- 직접 입력한 감정 3개를 64개 학생 시드로 검사했다. 576개 위치가 실제 걷기 지형 안에 생성됐고, 말의 순서·다른 말의 숨김 여부로 해당 말의 자리가 바뀌지 않았다. 모든 식물끼리의 충돌을 전수 검사한 것은 아니다.
- 기존 게시판의 익명화·공개 답 최소 개수·교사 검토·수정 시 공개 철회, 공감의 경험 조건·중복 방지, 승선·잠수 취소/건너뛰기 검사를 통과했다.
- 검증본은 Firebase SDK와 초기화를 제거하고 connect-src 'none'으로 외부 데이터 접속을 막았다. 시연 학급 생성기는 실행하지 않았다. 실제 후보에는 원래 인증·DB 연결만 남기고 가상 계정과 로컬 테스트 코드는 넣지 않았다.
- 별도 시험 폴더에서 후보 적용 → 이전 화면 복원을 실행해 파일 내용이 일치함을 확인했다. 관계없는 파일은 유지되고 추가 수정이 있는 index.html은 덮어쓰기를 거부했다. 실제 프로젝트 index.html은 교체하지 않았다.

검사 명령은 release/README.md에 있다.
